    10→# PPT creation, editing, and analysis
    11→
    12→## Overview
    13→
    14→A user may ask you to create, edit, or analyze the contents of a .pptx file. A .pptx file is essentially a ZIP archive containing XML files and other resources that you can read or edit. You have different tools and workflows available for different tasks.
    15→
    16→## Reading and analyzing content
    17→
    18→### Text extraction
    19→
    20→To read the text content of a presentation, convert it to markdown:
    21→
    22→```bash
    23→python -m markitdown path-to-file.pptx
    24→```
    25→
    26→### Raw XML access
    27→
    28→For comments, speaker notes, slide layouts, animations, design elements, or complex formatting, unpack the presentation and inspect its raw XML.
    29→
    30→#### Unpacking a file
    31→
    32→```
    33→python ooxml/scripts/unpack.py <office_file> <output_dir>
    34→```
    35→
    36→**Note**: `unpack.py` is at `skills/pptx/ooxml/scripts/unpack.py` relative to the project root. If not found, run `find . -name "unpack.py"` to locate it.
    37→
    38→#### Key file structures
    39→
    40→| Path | Contents |
    41→|------|----------|
    42→| `ppt/presentation.xml` | Main metadata and slide references |
    43→| `ppt/slides/slide{N}.xml` | Per-slide content |
    44→| `ppt/notesSlides/notesSlide{N}.xml` | Speaker notes |
    45→| `ppt/comments/modernComment_*.xml` | Slide comments |
    46→| `ppt/slideLayouts/` | Layout templates |
    47→| `ppt/slideMasters/` | Master slide templates |
    48→| `ppt/theme/` | Theme and styling |
    49→| `ppt/media/` | Images and other media |
    50→
    51→#### Typography and color extraction
    52→
    53→**When emulating an existing design**, extract typography and colors before starting:
    54→
    55→1. **Theme file** — `ppt/theme/theme1.xml`: colors (`<a:clrScheme>`), fonts (`<a:fontScheme>`)
    56→2. **Slide content** — `ppt/slides/slide1.xml`: actual font usage (`<a:rPr>`) and colors
    57→3. **Global search** — grep for `<a:solidFill>`, `<a:srgbClr>`, and font references across all XML files

   207→1. `<work_dir>/slides/global.css` — the deck-wide stylesheet that EVERY slide will `<link>` into its `<head>`. Bake in:
   208→     • You must use the font size /font style/color in the global.css, do not redefine it in each html
   209→     • CSS variables for the chosen palette: `--bg`, `--primary`, `--accent`, plus any tonal stops you need.
   210→     • `@import` lines for the chosen Google Fonts and a `:root` typography scale (title / subtitle / body / footnote sizes — see SLIDE QUALITY BAR).
   211→     • Reusable utility classes for the slide canvas (e.g. `.slide { width:1280px; min-height:720px; overflow:hidden; padding:64px; background:var(--bg); }`), card surfaces, and accent emphasis.
   212→     • NO per-slide layout CSS — that lives inside each slide's HTML. Keep this file under ~150 lines.
   213→     • Avoid CSS class collisions with Tailwind utilities
   214→          When the slide loads Tailwind via <script src="https://cdn.tailwindcss.com">, the CDN injects its utility styles into <head> after your <link
   215→          rel="stylesheet">. Custom classes that share a name with a Tailwind utility lose the cascade (same specificity, Tailwind comes later) and get silently
   216→          overridden.
   217→          Critical example: Do not name heading classes .h-1 / .h-2 / .h-3. In Tailwind these are height utilities (.h-1 = 4px, .h-2 = 8px, .h-3 = 12px). Applied to
   218→          a heading, the box collapses to a few pixels while the text still renders at full size — the heading visibly overlaps the element below it.
   219→     • Because `global.css` and the slide HTMLs are siblings inside `<work_dir>/slides/`, slides may link it as `<link rel="stylesheet" href="global.css">` (relative). 
   220→     • keep these in mind！！！ Global CSS scope — typography tokens only, no typography classes.Define typography design tokens (--font-heading, --font-body, --font-cn, --font-num, --fs-display, --fs-h1, --fs-h2, --fs-h3, --fs-body, --fs-small, --fs-micro) on :root in
   221→      global.css Do not ship pre-baked typography classes like .h-display / .h-1 / .h-2 / .h-3 / .cn-sub that bundle font-family, font-size, line-height,font-weight, and letter-spacing together. (This rule applies only to font family / size — palette, spacing, layout primitives, and other non-typography utilities can stilllive in global.css as before.) keep these in mind！！！

   380→## Editing an existing PowerPoint presentation（pptx）
   381→
   382→Pick the approach by what you're editing:
   383→
   384→- **Approach A — `python-pptx` script** — preferred for text replacement, deleting/reordering slides, and any edit that should preserve fonts/colors/layout. Simpler and safer than raw XML for content swaps.
   385→- **Approach B — raw OOXML** — required for animations, transitions, comments, speaker notes XML, theme tweaks, custom layout edits — anything `python-pptx` can't reach.
   386→
   387→### Approach A — `python-pptx` text replacement (preferred for text edits)
   388→
   389→**Workflow**
   390→
   391→1. **Inventory the deck** — walk every slide, recurse into GROUP shapes (`shape_type == 6`), `print(repr(para.text))`. Use the inventory as the source of truth for replacement keys; rendered text often contains hidden chars that won't survive copy-paste.
   392→
   393→2. **Helpers** — keep the build script short:
   394→
   395→   ```python
   396→   from pptx import Presentation
   397→   from pptx.enum.text import MSO_AUTO_SIZE
   398→   from pptx.oxml.ns import qn
   399→   from pptx.util import Emu, Pt
   400→
   401→   def iter_text_frames(shapes):
   402→       for s in shapes:
   403→           if s.shape_type == 6:                 # GROUP → recurse
   404→               yield from iter_text_frames(s.shapes)
   405→           elif s.has_text_frame:
   406→               yield s, s.text_frame
   407→
   408→   def _norm(s):                                  # strip soft breaks before matching
   409→       return s.replace("\x0b", "").replace("\r", "").strip()
   410→
   411→   def replace_in_paragraph(p, new_text):         # first-run replace preserves formatting
   412→       runs = p.runs
   413→       if not runs:
   414→           p.add_run().text = new_text; return
   415→       runs[0].text = new_text
   416→       for r in runs[1:]:
   417→           r._r.getparent().remove(r._r)
   418→
   419→   def apply_replacements(tf, mapping):           # full-frame match, then per-paragraph
   420→       m = {_norm(k): v for k, v in mapping.items()}
   421→       full = "\n".join(p.text for p in tf.paragraphs)
   422→       if _norm(full) in m:
   423→           parts = m[_norm(full)].split("\n")
   424→           for i, p in enumerate(tf.paragraphs):
   425→               replace_in_paragraph(p, parts[i] if i < len(parts) else "")
   426→           return
   427→       for p in tf.paragraphs:
   428→           if _norm(p.text) in m:
   429→               replace_in_paragraph(p, m[_norm(p.text)])
   430→
   431→   def delete_slide(prs, idx):                    # call high-index first
   432→       sld = list(prs.slides._sldIdLst)[idx]
   433→       prs.part.drop_rel(sld.get(qn("r:id")))
   434→       prs.slides._sldIdLst.remove(sld)
   435→   ```
   436→
   437→
   438→
   439→**Budget every shape BEFORE generating replacement text (do this first)**
   440→
   441→Most overflow bugs come from generating copy without knowing the target box's capacity. Before drafting any replacement, walk the deck once and emit a capacity manifest — then feed it to the content step as a hard constraint.
   442→
   443→For each text-bearing shape collect: `slide_idx, shape_id, w_cm, h_cm, font_pt, orig_text, orig_len`. Derive:
   444→
   445→- `chars_per_line ≈ w_cm / (font_pt × 0.014)` for CJK; multiply by ~2 for Latin. Mixed text: weight by character class.
   446→- `lines ≈ h_cm / (font_pt × 0.0185)` (line-height ≈ 1.3).
   447→- `budget = min(chars_per_line × lines, orig_len × 1.1)`. The template designer already tuned `orig_len` for readability — treat it as the ceiling, not a starting point.
   448→- `role = "label"` if `h_cm < 1.5` OR `orig_len ≤ 8` OR `font_pt ≥ 20`; else `"body"`.
   449→
   450→Rules the generation step MUST obey:
   451→- **Label boxes**: short phrase only. No full sentences, no trailing punctuation, no "term + explanation" expansion. Hard cap = `max(orig_len, 8)`. SWOT tiles, timeline tags, KPI labels all fall here.
   452→- **Body boxes**: stay within `budget`. Font size is inherited from the template; shrinking is a last resort, not plan A.
   453→- If the content is genuinely longer and the layout permits, **grow the box itself** (`widen_to_fit(shape, Emu(...))` — see below) rather than shrinking the font. Check first that `left + width` won't collide with the next shape.
   454→
   455→**Handling long replacement / unwanted wrapping after replacement**
   456→
   457→When a longer replacement wraps to a new line, apply remedies in this order (cheapest first):
   458→
   459→```python
   460→def widen_to_fit(shape, max_grow_emu=Emu(0)):
   461→    """Let PowerPoint size the shape to its text. Pass max_grow_emu>0 to also
   462→    grow the explicit width (centered on the original position) before sizing."""
   463→    if max_grow_emu:
   464→        shape.left -= max_grow_emu // 2
   465→        shape.width += max_grow_emu
   466→    shape.text_frame.word_wrap = True
   467→    shape.text_frame.auto_size = MSO_AUTO_SIZE.SHAPE_TO_FIT_TEXT
   468→
   469→def shrink_text_to_fit(shape):
   470→    """Keep the box fixed; let PowerPoint shrink the font to fit."""
   471→    shape.text_frame.word_wrap = True
   472→    shape.text_frame.auto_size = MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE
   473→```
   474→
   475→1. **Budget first (preferred).** Check `shape.width` × `font_size` from inventory and trim the replacement so it fits the original visual budget. Numeric badges / small label boxes (`width ≤ 0.7"`, `font_size ≥ 16pt`) hold ~3–4 chars max.
   476→2. **Widen the shape** with `widen_to_fit(shape, Emu(...))` when the content is genuinely longer and there's free space next to it. Always check the shape isn't going to collide with a neighbor first (compare `left+width` against the next shape's `left`).
   477→3. **Shrink the font** with `shrink_text_to_fit(shape)` only for tight-layout boxes (table cells, numeric badges) where widening would break the grid. Last resort — it visibly breaks the typographic rhythm.
   478→
   479→Skip `word_wrap = False`: it makes text overflow the box invisibly in PowerPoint and looks broken when exported.
   480→
   481→**Critical gotchas**
   482→
   483→- **Soft line breaks (`\x0b`)** silently break exact-match. Always `_norm()` both keys and lookups.
   484→- **GROUP shapes** (`shape_type == 6`) hide text frames — recurse.
   485→- **First-run replace** preserves formatting; `paragraph.text = ...` destroys it.
   486→- **Short tokens collide.** `"01"`, `"%"`, `"18"` recur across slides — keep identity mappings or scope per slide index, never global cross-mappings like `"18": "12"`.
   487→- **Delete slides high-index first** — deleting index 5 first shifts every later index down by one.
